# 原始规格传递与规划上下文

本轮修复的是同一类上下文丢失，而非新增提示词系统：分层子规划、局部重规划和
mutation 测试加固原来只收到派生需求或当前实现，缺少原始规格。它们可能继续改写
错误摘要，或把实现的偶然行为固定成新测试。现由控制器传入 PlanInputs.spec / Run.spec，
复用已有 SPEC_AUTHORITY 和 spec_context；builder 与异常测试审核的现有约定保持一致。

普通规划、模块规划、边界作者/审核和测试设计也复用同一优先规则。原规格保持规范性；
契约按需求 ID 补充接口形状、状态归属、顺序和跨模块选择，不重复解释已有验证条件和
算法公式。审核仍拒绝显式矛盾、不可用接口、未固定的跨模块输出形状；不能因为没有
复述原规格就要求补写整份行为规范。没有自动忽略任何有效审核意见或降低最终验收。

子模块现在共用规划指令、原始规格和固定经验规则组成的项目级前缀；模块归属、选定
需求、接口和反馈放在动态部分，仍完整传给模型。不同模块与重试不再因模块名字不同而
打断这一共享边界。错误反馈、实现失败和 mutation survivor 仍在动态部分，不混入
原始规格。原有模型路线、1M DSF 容量、写入所有权、冻结测试、账本及预算限制未改动。

复用了现有常量、上下文封装和事务状态；没有新增通用工具或序列化实现，也没有新增
模型调用。旧已结算规划遇到请求变化仍按既有账本报冲突，不自动改写历史或重新付费。

定向证据覆盖实际控制器调用，而不只检查提示词函数：分层计划含一次局部修正并完成
执行，三次子模块调用带有原规格且共享前缀一致；并发局部重规划保留原规格并完成；
测试加固调用带原规格，仍须通过“新测试有效杀死 survivor”的既有门。
