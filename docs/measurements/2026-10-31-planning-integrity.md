## 单个分片应在冻结前拒绝命名覆盖

可复现问题：test_shard 只枚举 AST 中的测试方法和需求标记，遗漏 Python 最终名称绑定。
重复方法直到最终 assemble 才被拒绝；给测试方法重新赋值会在加载/执行时才失败，
此时冻结测试已经成为后续 builder 无权修复的输入。重复 class、fixture 钩子以及
导入覆盖还可能丢掉原检查。不能把 AST 声明数量直接当实际执行覆盖。

扩展共享 fixture_errors，在单个分片阶段拒绝直接、无条件的名称覆盖/删除；同样适用于
最终计划及测试修复。保留同名的跨 class 方法、属性 getter/setter 和无赋值类型注解，
不猜测条件分支、动态 setattr 或其他运行期绑定，也不宣称能证明验收期望正确。
修复只重新请求有问题的分片，其他已合格分片不重做。
另去掉提示中的任意 120 行目标，保留实际请求容量上限与必要覆盖要求。
