## 容量与缓存到底改了什么

旧 `DshClient.input_limit = 40 * 1024` 是本仓库的字节护栏，不是 DSF 模型容量。
已撤销它与 6 KB 依赖实现预算，保留沿调用图选择的任务相关实现；没有把整个仓库广播给
所有节点。类定义已包含的方法不重复装载，补读选择器排序固定。

官方模型元数据给出 **1,048,576 token** 的输入输出合计窗口；本机 DSH SDK 的默认
`contextWindow` 为 **1,000,000 token**。客户端不再以 40 KiB 截短这一路径。
`DshClient.context_window_tokens` / 评测 manifest 记录官方容量；实际 token 限制由厂商执行。
16 MiB 仅是本地文本载荷/内存护栏，不能解读成 token 窗口。默认输出预算仍为 8,192 token。
依据：[官方模型规格](https://api-docs.deepseek.com/quick_start/pricing/)、
[模型元数据说明](https://api-docs.deepseek.com/api/list-models/)，2026-10-30 核实。

本轮 DSF 请求最大 **98,387 字节**，最大实际输入 **23,760 token**；恢复试验中达到
124,339 字节、30,362 输入 token。说明真实任务已经使用超过旧限制的上下文，
**不是填满 1M token 的极限或准确率压力测试**。
本轮全部 DSF build 请求共用一个完整项目前缀 `cf863b0b7b98`，不再因旧小窗口裁掉 map
而切换前缀。缓存命中仍以真实厂商回执为准，不以指纹相同替代命中证明。
